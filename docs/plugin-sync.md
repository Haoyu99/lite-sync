# 插件同步与网页登录（0.2.0）

## 同步规则

新库初始化后默认同时同步笔记、附件和社区插件。文件同步继续保留既有冲突副本规则；插件同步由第一台完成同步并取得初始化资格的设备提供基准。初始化中断时原设备可以继续，其他设备等待其完成，避免把半份插件库当成完整基准。

插件的标准文件是 `manifest.json`、`main.js`、可选的 `styles.css` 和 `data.json`。每个插件作为一个完整包加密、传输和保留版本，不把这些文件放进旧的笔记变更流。额外资源、插件自建缓存及其他 Obsidian 配置本次不参与同步。标准插件文件说明见 [Obsidian 插件结构](https://docs.obsidian.md/Plugins/Getting+started/Anatomy+of+a+plugin)。

- `lite-sync` 和 `obsidian-livesync` 永久排除，后台另可按插件 ID 排除。
- 不同步 `hotkeys.json`、`community-plugins.json`、窗口布局、主题或外观。每台设备独立决定插件是否启用。
- 其他设备首次加入：同名插件采用云端基准，替换前备份本地版本。本机独有插件保留在本机，不在首次加入时自动发布；此后本地修改可以上传。
- 新插件下载后保持未启用；手机跳过声明 `isDesktopOnly` 的插件。
- 在本机卸载后，该设备持久记录这个选择，不会被下次同步重新安装；不从云端或其他设备删除插件。本机重新安装后可继续同步。
- 同步配置可单独关闭。关闭的设备仍能同步代码，但保留自己的配置，也不会删除云端已有配置。

## 冲突与应用

插件包使用当前版本校验，过期写入返回冲突，不覆盖新版本。

配置有共同基准时按 JSON 字段三方合并。同一字段冲突取云端值，本地版本另存备份；代码两端同时变动时采用云端包，保留本地备份。没有共同基准的首次接收同样先备份再应用。

接收包先完整解密并校验插件 ID、文件名单及 manifest。已启用插件在写入前暂停、写入后重新加载，不改变其持久启用列表。这个动作通过经过运行时检查的 Obsidian 插件管理器适配层实现；若当前 Obsidian 不具备所需方法，则停止应用并显示错误，不能假装更新成功。

只修改上述四个标准文件，保留插件目录内其他本地文件。应用前在 `<configDir>/lite-sync-staging/` 写恢复记录，在 `<configDir>/lite-sync-backups/<插件ID>/` 保存本地包。写入失败回滚；崩溃后下次启动先恢复中断事务。若插件在卸载回调中又保存了配置，则保留这些修改，等待下一轮重试。

默认每 30 秒扫描一次插件目录，也可手动立即同步；笔记编辑仍按防抖间隔同步。插件同步错误会单独显示在状态栏和日志中，不阻止笔记同步。

## 同步进度与故障排查

- 文件和插件同步共用一条进度提示，持续超过 600 ms 才显示；整轮结束后在同一提示中保留结果 6 秒。后台检查没有变更时不弹窗，手动同步会显示结果。尚有待处理文件或插件未完成时，不显示整轮同步完成。
- 首次下载最多预取 3 个文件，写入和索引持久化仍逐个执行。同步索引复用 IndexedDB 连接，退出时关闭。同步过程中每隔约 5 秒上报设备游标和待处理数量，结束时再次上报。
- 单次网络请求超过 30 秒会报超时，下一轮同步重试；保留未完成下载的索引记录。Obsidian 的网络接口不能取消底层请求，超时后迟到的响应不会继续应用到本地。
- 「显示同步日志」可查看网络下载、解密校验、本地写入和索引保存各阶段的毫秒耗时，用于定位真实客户端上的停顿。
- Windows 本地会将不支持的文件名和目录名转换为可用的名称，例如 `14-> 15.md` 保存为 `14-＞ 15.md`；处理保留名称和末尾空格、句点，并在名称碰撞时添加后缀，避免覆盖本地文件。云端路径、文件 ID 和其他设备的原始文件名保持不变。
- 本地名称对应关系保存到同步索引，后续编辑、删除、重命名和新增子文件仍作用于原来的云端路径。升级后会自动重试先前因文件名被跳过的文件，无需重新配对。正文保持原样，不改写其中的链接；引用原始特殊文件名的链接在 Windows 上可能需要使用本地适配名称。

## 网页登录与解锁

- 服务器会话固定有效 7 天，访问或刷新不延长这 7 天；取消原来 30 分钟闲置过期。
- 默认勾选「在此浏览器记住解锁 7 天」。口令不保存；主密钥用浏览器本地不可导出的 AES 密钥封装，与当前会话、口令封装版本和到期时间绑定，放在 IndexedDB 中。
- 刷新或重新打开页面时先核对服务器会话，再恢复本地解锁。关闭浏览器的存储功能时仍可登录，但会提示无法记住解锁。
- 开启双重认证后，新浏览器首次登录需要验证码或恢复码。验证成功发放独立的 HttpOnly、Secure、SameSite=Strict 信任 Cookie，数据库仅存凭据哈希。
- 受信任浏览器在 7 天会话到期后只需重新输入口令。信任凭据最长一年，并在登录时轮换续期；浏览器清理数据后需重新验证。
- 普通退出清除当前服务器会话和本地解锁缓存，保留浏览器信任。「撤销此浏览器信任并退出」同时删除其信任凭据。
- 修改口令或 CLI 重置双重认证使所有会话及信任失效。修改双重认证设置也会清除其他登录会话和旧信任。
- 修改口令、关闭双重认证、生成恢复码等敏感操作仍按各自接口要求校验口令及当前验证码。

## 数据与重新初始化

本项目处于内部测试阶段，只保留一份当前 SQLite 结构，不维护旧结构升级分支。新数据目录一次性创建笔记、插件同步、浏览器信任等全部表；正常重启沿用现有数据，不会清空。

本次部署按用户要求清空服务端数据库及密文对象，重新初始化。原口令、双重认证、历史和设备配对失效，需要重新设置并配对；客户端本地笔记和插件保留。先让希望作为基准的设备使用 0.2.0 完成一次同步，再逐台加入其他设备。

插件包在密文对象存储中保存，`data` 备份覆盖它们。新库默认开启插件及配置同步。

当前没有连接真实 Obsidian 设备的自动化环境；生命周期适配与磁盘失败恢复通过模拟运行时测试验证，仍需在实际桌面和手机客户端验收。
