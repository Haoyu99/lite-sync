# lite-sync 全流程说明

这份文档按时间顺序讲一遍 lite-sync 从部署到日常使用、再到出问题时怎么办。它是给人看的说明，技术细节以 [design.md](design.md) 为准。

## 0. 先认识几个名词

| 名词 | 通俗解释 | 存在哪里 |
|---|---|---|
| 口令 | 你在 Bitwarden 里生成的一段话，例如 `河马-台灯-雨伞-星期三-菠萝`。整个系统里只有它需要你保管 | 你的 Bitwarden，加一份纸质备份。服务器上没有 |
| 验证码 | 手机上 Google Authenticator 显示的 6 位数，每 30 秒变一次 | 你的手机 |
| 恢复码 | 10 个一次性代码，手机丢了时代替验证码登录 | 纸质备份或 Bitwarden |
| salt（盐） | 一段公开的随机数，防止别人提前算好"常见口令对照表" | 服务器 |
| 根钥匙 | 口令加 salt 慢慢算 60 万轮得到。用完就丢 | 只在浏览器或插件内存里出现一瞬间 |
| 登录钥匙 | 从根钥匙派生出来，用来向服务器证明"我知道口令" | 服务器只存它的哈希 |
| KEK（解锁钥匙） | 从根钥匙派生出来，只用来锁住或解开主密钥 | 只在内存里出现一瞬间 |
| MK（主密钥） | 初始化时随机生成的 32 字节，所有文件实际都用它加密。生成后不变 | 服务器上只存"被 KEK 锁住的版本"；每台已加入的设备本地存一份 |
| 设备令牌 | 设备访问服务器的"门禁卡"。只能进门，看不懂数据 | 设备本地；服务器只存哈希 |
| 配对码 | 添加设备时用的一次性代码，10 分钟内有效 | 用完作废 |
| 文件 ID | 文件路径经过带钥匙的指纹计算（HMAC）得到的一串字符，例如 `3b7c9e41…` | 服务器用它代替文件名 |
| rev | 单个文件的版本号：1、2、3…… | 服务器 |
| seq | 全局序号，服务器每收到一次修改就加一 | 服务器；每台设备记住自己处理到第几号 |

钥匙之间的关系：

```
口令 + salt ──(算 60 万轮)──> 根钥匙
                               ├─> 登录钥匙 ──> 交给服务器验证
                               └─> KEK ──解开──> MK
                                                 ├─> 内容钥匙：加密文件内容
                                                 ├─> 元数据钥匙：加密文件名和修改时间
                                                 ├─> ID 钥匙：把文件名变成文件 ID
                                                 └─> 配置钥匙：加密统一配置
```

箭头都是单向的：从右边推不回左边。所以服务器拿着登录钥匙的哈希和被锁住的 MK，也得不到口令和 MK。

## 1. 部署服务器

你在服务器上做：

1. 准备 `docker-compose.yml` 和域名，在 1Panel 里新建反向代理站点，指向 `http://127.0.0.1:28470` 并开启 HTTPS。
2. 在环境变量里设置 `LITE_SYNC_SERVER_KEY`，一段随机字符，用来加密服务器上的 TOTP 密钥。
3. `docker compose up -d` 启动。
4. `docker logs lite-sync` 查看日志，里面有一条一次性初始化链接。

此时服务器上还没有任何钥匙和数据。

## 2. 初始化（只做一次）

在浏览器里打开初始化链接：

1. 用 Bitwarden 生成一个 5 个以上单词的密码短语，填进去。
2. 浏览器在本地完成这些计算，不经过服务器：
   - 生成 salt；
   - 口令 + salt 算出根钥匙，再分出登录钥匙和 KEK；
   - 随机生成 MK，用 KEK 锁住。
3. 浏览器上传三样东西：salt、登录钥匙、被锁住的 MK。服务器把登录钥匙再哈希一次后保存。
4. 页面显示二维码。用 Google Authenticator 扫描，输入 6 位验证码确认。
5. 页面显示 10 个恢复码。保存好，同时把口令和恢复码抄一份纸质的放在家里。

完成后，服务器有了 salt、登录钥匙的哈希、被锁住的 MK、加密的 TOTP 密钥，但没有口令，也没有 MK 明文。初始化链接随即作废。

## 3. 登录后台

打开 `https://你的域名/admin`：

1. 页面先向服务器要 salt。
2. 你输入口令（Bitwarden 自动填充）和手机上的验证码。
3. 浏览器在本地算出登录钥匙和 KEK，只把**登录钥匙和验证码**发给服务器。
4. 服务器核对两项，都对就放行。
5. 浏览器下载被锁住的 MK，用 KEK 在本地解开，放在页面内存里。
6. 现在你能看到设备列表、文件目录、文件内容、历史版本。文件名和内容都是浏览器下载密文后在本地解密的。
7. 关闭页面，或者 30 分钟不操作，内存里的 MK 就会被丢弃。

只有口令没有手机，或者只有手机没有口令，都登录不了。

## 4. 加入第一台设备（Mac，内容最全的那台）

1. 先在所有设备上停用 LiveSync，并把库复制一份作为备份。
2. 在后台点"添加设备"，得到配对码，例如 `K7QM-29XD`。
3. 在 Mac 上用 BRAT 安装 lite-sync 插件，打开设置，填写服务器地址和配对码。
4. 服务器核对配对码，给这台 Mac 发一张设备令牌，登记设备名"Mac"、平台、插件版本。配对码作废。
5. 插件提示输入口令。它在本地算出 KEK，下载被锁住的 MK 并解开，把 MK 存进这台 Mac 的本地存储，然后丢掉口令。口令输错时会解不开，插件提示重新输入。
6. 插件开始首次上传：逐个读取库里的文件，加密后上传（过程见第 6 节）。状态栏显示 `↑ 248 待上传`，逐渐减少到 `✓ 已同步`。

## 5. 加入其他设备（Windows、Ubuntu、iPhone）

每台设备重复第 4 节的第 2 到 5 步。不同的是，这些设备本地已经有一份库，云端也有了一份，插件会逐个比较：

| 情况 | 处理 |
|---|---|
| 本地和云端内容一样 | 直接关联，不传输 |
| 只有本地有 | 上传 |
| 只有云端有 | 下载 |
| 两边都有但内容不同 | 云端版本放在原路径，本地版本另存为 `笔记 (冲突 iPhone 10-30 14:02).md` |

整个过程不会覆盖任何文件。全部完成后，到后台检查冲突副本，确认后删除不需要的，再卸载 LiveSync。

iPhone 上用 BRAT 安装，同样填服务器地址和配对码，口令可以由 Bitwarden 的 iOS 自动填充提供。

## 6. 日常：在 Mac 上改一篇笔记

你修改 `1. 『📅 Daily』/2026-10-30.md`，停笔约 2 秒后：

**Mac 这边**
1. 计算内容指纹（SHA-256），和上次同步时的指纹比较，确认确实改了。
2. 放进待上传队列。队列保存在磁盘上，就算 Obsidian 此时崩溃，下次启动也会继续上传。
3. 用 ID 钥匙把路径变成文件 ID `3b7c9e41…`。
4. 用内容钥匙加密内容，用元数据钥匙加密路径、修改时间和指纹。
5. 发给服务器，同时说明"我是基于第 4 版改的"。

**服务器这边**
1. 核对设备令牌。
2. 核对版本：当前确实是第 4 版，就接受写入，记为第 5 版，全局 seq 加一。
3. 旧的第 4 版继续保留。
4. 通过 WebSocket 通知其他在线设备："seq 到 1023 了"。

**iPhone 这边**
1. 收到通知，问服务器"seq 1022 之后有什么变化"，拿到文件 ID 和加密的元数据。
2. 用元数据钥匙解出路径，用内容钥匙解出内容。
3. 重新计算指纹，和元数据里的对比，一致才写进库。
4. 如果你此刻正在 iPhone 上编辑这篇笔记，并且最近 5 秒内还在输入，就稍后再写入，避免打断你。

一般几秒内就能在 iPhone 上看到修改。

整个过程中服务器看到的只是：有一台叫"Mac"的设备，在 14:02 更新了 `3b7c9e41…` 这个文件，密文大小 1342 字节。

## 7. 离线时两台设备改了同一篇笔记

例如在飞机上用 iPhone 改了第 3 段，同时 Mac 改了第 7 段，两边都基于第 5 版。

1. Mac 先联网，上传成功，成为第 6 版。
2. iPhone 联网后上传，说"我基于第 5 版"。服务器发现当前已是第 6 版，返回"版本已过期"（409），拒绝写入。
3. iPhone 从服务器取回第 5 版（共同祖先）和第 6 版（Mac 的修改），和自己的版本做三方合并：
   - 两边改的不是同一处：自动合并成功，上传为第 7 版。两处修改都保留。
   - 两边改了同一处：原路径保留第 6 版，iPhone 的版本另存为 `笔记 (冲突 iPhone 10-30 14:02).md` 并上传。你有空时打开对比，留下想要的内容。

不会弹对话框阻止你继续工作，也不会悄悄丢掉任何一边的修改。

## 8. 删除和重命名

- **在 Obsidian 里删除文件**：删除会同步到其他设备，但服务器保留所有历史版本，至少 90 天内都能在后台找回。
- **文件在扫描时不见了，但你没有删**（例如 iCloud 把它移出了本机）：不当作删除，插件会重新下载。
- **重命名**：新路径写入和旧路径删除一次性提交，不会出现只做了一半的情况。
- **一次同步要删除或覆盖超过 20 个文件**：插件暂停，等你确认。防止误操作波及整个库。

## 9. 回滚

在后台：

- **单个文件**：打开文件历史，选一个旧版本，点"恢复"。系统用旧内容生成一个新版本，原来最新的版本仍然保留，所以恢复本身也可以撤销。
- **整个库**：选择一个时间点，例如"昨天 20:00"。系统只为和那时不同的文件生成新版本。整个操作记为一次批量操作，可以一键撤销。

不存在"用旧设备重建远程数据库"这种操作，旧数据只会以新版本的形式回来，不会抹掉已有的版本。

## 10. 修改 `.obsidian` 配置

例如在 Mac 上给 image uploader 换了图床设置：

1. Obsidian 不为 `.obsidian` 目录发出文件事件，插件每 30 秒扫描一次，发现 `plugins/obsidian-image-uploader/data.json` 变了。
2. 和笔记一样加密上传。
3. 其他设备收到后写入。如果两边都改了这个 JSON，按键合并，同一个键冲突时采用云端的值，本地值留在历史里。
4. 如果变的是插件代码（`main.js`），插件提示你重新加载 Obsidian。

`workspace.json`（窗口布局）和 lite-sync 自己的文件夹永远不同步。

## 11. 更新 lite-sync 插件

1. 在 BRAT 里手动点更新。不会自动更新。
2. 各设备不需要同时更新。新版本能读取旧格式，服务器也继续支持旧版本插件。
3. 如果某台设备的插件太旧，服务器会让它进入只读模式并提示更新，不会删除或覆盖任何文件，也不会要求重建。

## 12. 出问题时怎么办

### 12.1 手机丢了

1. 用电脑登录后台。验证码在丢失的手机上，所以用一个恢复码代替。
2. 吊销这台手机的设备令牌。它再也无法访问服务器。
3. 在新手机上重新绑定 Google Authenticator。
4. 那台手机里存着 MK。如果担心有人同时拿到手机和服务器数据，执行"轮换主密钥"（第三阶段功能）：生成新 MK，在浏览器里把所有文件重新加密，其他设备重新输入一次口令。

### 12.2 验证码和恢复码都没了

在服务器上执行 `docker exec lite-sync reset-2fa`，下次登录时重新绑定。这需要服务器的 shell 权限，别人没有这个权限。

### 12.3 忘了口令

口令只用于登录后台和让新设备解开主密钥，插件里没有重设口令的入口。口令丢失时：

- 已加入的设备照常同步，不受影响。
- 后台无法登录，也无法加入新设备。
- 没有找回办法。只能在内容最全的设备上重新初始化服务器并重新上传，历史版本会丢失。

所以口令必须存进 Bitwarden，并另外保留一份纸质备份。

### 12.4 服务器挂了

- 各设备照常编辑，修改留在待上传队列里。
- 服务器恢复后自动上传。
- Bitwarden 和 lite-sync 在同一台服务器上时，Bitwarden 客户端的本地缓存一般还能用来查口令；缓存没有时，用纸质备份。

### 12.5 服务器数据泄露

对方拿到的是：salt、登录钥匙的哈希、被锁住的 MK、所有密文。

- 看不到文件名和内容。
- 唯一的办法是逐个猜口令，每猜一次算 60 万轮。随机的 5 个单词基本猜不出来。
- 建议做法：修改口令，并执行"轮换主密钥"。

### 12.6 服务器被别人完全控制

除了第 12.5 节的情况，对方还可能篡改后台网页的代码，在你下次登录时偷走口令。

- 插件不受影响，因为插件代码在你的设备上，不从服务器加载。
- 怀疑服务器被入侵时，不要在线上后台输入口令，改用本地打开的后台（`npm run admin:local`）。

## 13. 你需要保管的东西

| 东西 | 放在哪里 | 丢了会怎样 |
|---|---|---|
| 口令 | Bitwarden + 纸质备份 | 已有设备照常同步，但无法登录后台或加入新设备 |
| Google Authenticator | 手机 | 用恢复码登录 |
| 恢复码 | 纸质备份（可再存一份在 Bitwarden） | 用服务器命令重置 |
| `LITE_SYNC_SERVER_KEY` | 服务器的环境变量文件，随服务器备份 | 需要重新绑定 TOTP |
| 服务器数据目录 | 定期备份 | 用设备上的库重新上传，但历史版本会丢失 |
